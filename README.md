# Рынок под давлением — деловая игра (спрос, предложение, эластичность)

Цифровая версия деловой игры для пары по экономике: **5 команд по 4 человека** управляют
условными предприятиями, покупают ресурсы на аукционе, назначают цену товара и считают
выручку, прибыль и эластичность. Организаторы (4 человека) ведут игру из **админ-панели**.

Формулы расчётов от игроков скрыты — команды считают сами; у организаторов есть эталонный
калькулятор и справочник.

---

## Быстрый старт

1. Нужен **Node.js 16+** (nodejs.org).
2. Запустите игру:
   - двойной щелчок по **`start.bat`**, или
   - в терминале: `node server.js`.
3. Консоль покажет адреса:
   - у организаторов (на этом же ноутбуке): `http://localhost:3088`
   - у команд (телефоны в том же Wi-Fi): `http://<IP-ноутбука>:3088` — IP напечатан в консоли.

### Пароли

| Кто | Пароль |
|---|---|
| Организаторы (`/admin.html`) | `admin` |
| Команда A — Хлеб | `A2026` |
| Команда Б — Мебель | `B2026` |
| Команда В — Одежда | `C2026` |
| Команда Г — Электроника | `D2026` |
| Команда Д — Стройматериалы | `E2026` |

> Внешние зависимости не нужны: сервер работает на чистом Node.js, работает офлайн по локальной сети.

## Как идёт игра (11 фаз админ-панели)

| Фаза | Кто активен | Что происходит |
|---|---|---|
| Лобби | команды | Студенты заходят с телефонов по паролям |
| Знакомство | ведущий | Правила, цель — максимальный итоговый капитал |
| Раунд 1 · Анализ спроса (7 мин) | команды | Изучают свою таблицу спроса, ищут цену с максимальной выручкой |
| Раунд 2 · Аукцион (10 мин) | аукционист | Лоты: Сырьё 50 ед. (старт 100), Труд 30 (150), Энергия 30 (100). Ставки с телефонов или устно («Записать ставку») |
| Раунд 3 · Производство (5 мин) | команды | Выпуск упирается в самый дефицитный ресурс, максимум 10 ед. |
| Раунд 4 · Рынок и равновесие (7 мин) | аналитик | Команды фиксируют цену → «Свести рынок»: спрос, продажи, избыток/дефицит, выручка, прибыль |
| Раунд 5 · Эластичность спроса (7 мин) | команды + аналитик | Объявляется изменение цены; команды считают E и тип спроса; аналитик сверяет с эталоном сервера |
| Раунд 6 · Эластичность предложения (5 мин) | команды + аналитик | Событие (подорожание ресурсов / авария энергосети), расчёт E<sub>s</sub>, возможен второй аукцион |
| Раунд 7 · Итоговый расчёт (5 мин) | команды | Отчёты о прибыли и капитале |
| Итоги | все | Рейтинг по капиталу (победитель) и по баллам (максимум 60) |

### Баллы (максимум 60)
анализ спроса 10 · расчёт эластичности 15 · рациональная закупка 10 · определение предложения 10 · выручка и прибыль 10 · обоснование решений 5.

### Экономические данные (упрощённая модель)
- Капитал команды: 10 000 д.е. Максимальный выпуск: 10 ед.
- Рецепты на 1 единицу: Хлеб = сырьё+энергия · Мебель = сырьё+труд · Одежда = сырьё+труд · Электроника = сырьё+энергия · Стройматериалы = сырьё+энергия.
- Таблицы спроса (цена 100→500): Хлеб/Одежда/Стройматериалы — 10,8,6,4,2 (эластичный); Мебель/Электроника — 10,9,8,7,6 (неэластичный).
- Эластичность считается **методом средней точки**; эталон для 300→400: −1,40 (эластичные товары) и −0,47 (неэластичные). Примечание: в некоторых методичках для этого же примера указано −1,8 — это арифметическая ошибка источника, верьте панели.

## Управление и подводные камни

- **Коррекция денег** (банкир): вкладка «Команды» → «± деньги».
- **Ручные торги**: вкладка «Аукцион» → «Записать ставку» или «Продать вне аукциона».
- **События**: авария энергосистемы (энергии остаётся 10 ед.), налог с единицы товара (по умолчанию 100 д.е.), рост издержек; баннер виден всем командам.
- **Состояние сохраняется** в `state.json` автоматически (перезапуск сервера безопасен).
- **Сброс между группами**: вкладка «♻️ Сброс».
- Если студенты не открывают адрес — все должны быть в одной Wi-Fi сети, и при первом запуске разрешите Node.js доступ в «Брандмауэре Windows».
- Смена фаз и таймер — вручную; таймер показывает обратный отсчёт всем.

## Техническое

- Чистый Node.js (без npm-зависимостей), порт **3088** (переменная окружения `PORT`).
- Хранение состояния: файл `state.json` рядом с `server.js` (создаётся автоматически).
- Клиенты опрашивают сервер каждые 3 секунды — данные всегда актуальны, ничего не теряется при разрыве связи.
- Пароль админа задаётся в `server.js` (константа `ADMIN_PASS`).
